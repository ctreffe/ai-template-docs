# Philosophy

## Template Mission

Create and improve technical documentation, instructions and related documents
that help their intended readers understand, decide and act. Quarto maintains
one shared source basis for standardized outputs in multiple formats.

The central Review-Revision Workflow iteratively improves quality: review
rendered documents outside Codex, annotate them, then use revise-document to
evaluate feedback and transfer accepted revisions into maintained sources.
Multilingual documents are small subprojects with their own document context;
language variants share that context and stay aligned. investigate-question
builds and assesses sources and evidence for the document. Write concisely,
precisely and informatively, preserving what readers need to understand.
Technical review-document critique remains available; scientific peer-review
criteria are not a default requirement for every technical document.

## Mission Ownership

This section owns the source template's mission. In a derived project, retain it
as the inherited workflow purpose; PROJECT_CONTEXT.md owns the maintainer's
concrete project mission, outcome and boundaries. Do not substitute the template
mission for that local purpose. Maintainer domain judgment remains decisive at
both levels. Disclose actual human-AI collaboration clearly in template and
project READMEs without exposing sensitive content. The local
[alignment method](COLLABORATION.md#mission-alignment) governs reviews and
retrospectives; mission drift requires a maintainer decision, not silent rewriting.

Technical documentation is a maintained product, not a side effect. It should be accurate, reviewable, navigable, and useful for real tasks.

## Principles

- Documentation must reflect the current technical truth.
- The maintainer owns correctness, scope, structure, and publication.
- The assistant supports structure, drafting, consistency, and QA.
- Visuals should explain real interfaces, states, workflows, or decisions.
- Links should guide readers and preserve traceability.
- Sensitive material must be protected before it enters the collaboration context.
- Decisions that shape the documentation should be recorded.
- Milestones should leave the repository in a coherent state.
